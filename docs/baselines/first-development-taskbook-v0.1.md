# 调酒师开源版｜首轮开发任务书 v0.1

日期：2026-11-20  
用途：交给本地 Mac 开发者或编码助手，按已经收敛的方案推进第一批工程工作。  
状态：开发任务与验收要求；本文件不表示以下工程已经完成。

## 1. 目标与本轮交付边界

请先阅读《调酒师开源版_初版产品与技术方案_v0.1.md》。首版目标是：低频菜单栏项目收纳后，用户仍能找到正确项目、读取所需的真实状态、使用原菜单，且正在进行的操作与用户后来修改的布局不会被管理器覆盖。

产品范围已经决定，无须先重开一轮框架选型：

- Swift 6 语言模式与严格并发检查；AppKit 系统外壳，SwiftUI 设置与目录。
- 单进程模块化，系统操作只经唯一协调器；InventoryProvider、VisibilityBackend、AccessBackend 分开。
- 自有代码 MIT，官方发行版免费；核心离线，无账号或业务服务器。
- 两区、控制入口与全局快捷键、基本目录和别名过滤、真实项目访问、交互保护、本地配置与恢复为首版。
- 默认手动收起；没有可靠菜单结束证据时保持访问。
- 像素镜像、始终隐藏区、复杂搜索、预设、自动规则、顶部工具集和云同步后置。
- macOS 26 / Apple Silicon 为首个实测基线；27 独立实验。当前系统由实际环境决定，不要求操作者升级系统。

**本轮工程主任务是 M0/M1：使已有验证包在真实 Mac 上运行，并回答主要目标场景中，至少一条后端能否完成真实访问。** 可同时编写纯模型与必要适配骨架，但不要在后端问题未解决时先铺完整设置页、规则编辑器或主题系统。

若没有任何候选通过核心可达性，交付可复现的失败与下一项实验，保持技术预览状态。不要改写 P0 的含义来制造首版完成。

## 3. M0：真实环境与无管理器基线

### 3.1 建立可重复的工程起点

在实际解压的验证包目录内执行已有环境检查与构建入口：

~~~bash
python3 tools/preflight.py
bash scripts/build-macos.sh
~~~

保留 OS 版本与 build、CPU 架构、实际 Xcode／SDK、源码 hash、构建日志和退出码。不从当前日期、用户旧描述或工程 deployment target 推断支持状态。

若编译失败，做针对性修复；记录修改前后源码与构建输入 hash。只重跑与修复相关的检查和现有必要门槛，不把新结果贴到旧源码版本。

不要自动安装另一个 macOS 大版本，也不要修改系统访问控制来使试验可运行。需要系统授权的操作走正常设置流程，授权完成以实际观察为准。

### 3.2 跑无管理器基线

经操作者正常停用现有菜单栏管理器后，只运行 Fixture，验证同一 App 的 FA、Beta 动态计数、FC 三项：

- 左键、右键、Option、子菜单与持续计数；
- 菜单打开、保持和关闭过程；
- 真实日志与实际画面是否对应；
- 重排、退出重开后可观察属性的变化。

记录匿名机器别名、comparison_group_id、显示器逻辑点、缩放、刘海、前台 App、菜单栏自动隐藏、独立 Spaces 与权限 profile。不采集设备序列号、账号或无关菜单内容。

同一比较组的无管理器基线和候选使用相同前台 App、菜单占用与拓扑；Controller 的测试窗口若改变前台 App，应重新建立相符基线。

### 3.3 先确认恢复入口

每个候选开始之前，验证如何撤销本工具的限制以及如何退出。正常退出、强制结束、卡死和重启是四类不同情形，分别记录实际后果。

实验期间只运行一个管理器。遇到错误目标、输入被抢、系统隐私状态遮蔽或用户新布局被覆盖，停止继续扰动并保留原始失败；采取已验证的恢复步骤，不继续随机增加占位长度或重发动作。

## 4. M1：三个阻塞实验

### E26-A：唯一目标的 AX 访问

前置条件：目标属于当前进程生命周期，生产者和 Item 绑定唯一，且实际暴露所需 action。保留候选列表和不能确定的属性，不按 bundle 下的第一项决定目标。

制造刘海或总宽导致目标不可见的真实条件；向该目标只发一次实际支持的动作，然后独立观察：

1. 是否打开正确项目的原菜单；
2. 菜单位置是否可用，能否继续选择子项；
3. 动态状态是否仍可读；
4. 超时后是否已经出现菜单；
5. 关闭之后是否可继续正常使用。

每个 Item-action 分开记录。一次左键动作成功不推导为右键、Option 或其他项目成功。AX CannotComplete 或超时返回结果未知时，不盲目重发。

### E26-B：受限临时可见槽位

只存在于独立研究构建，默认关闭。仅在源项目真实可命中、目标槽足够、当前无冲突输入、身份与邻居可观察时，研究一次受限 Command-drag。

分别验证移动前身份、输入修饰键、移动后身份与菜单访问；恢复只针对自己已经确认作出的最小变更。用户中途手动重排后，必须放弃旧逆操作。

完全离屏、位于不可命中区域或没有可靠源对象的目标，不满足本实验前置。不能以负坐标投递或未经验证的窗口路由声称已解决。若必须依赖未文档化路由，另列候选、源码与回归成本；不静默并入正式路径。

### E27-A：原生 overflow

仅在实际 macOS 27 上运行该候选。先检查几何前置与总容量，拒绝不满足条件的计划，再观察原生 overflow。

三个同 App 项目必须分别完成真实菜单、右键、Option、子菜单、动态状态；同时验证时钟、通知中心、摄像头／麦克风状态及来源提示。出现一个 overflow 控件本身不足以判定通过。

六个 spacer 与 64 pt 余量是已有候选模型参数，不是平台保证。改变参数要成为新候选记录。保持公有几何与私有显隐断言分离；只读私有探针的存在性结果不能替代显隐或交互任务。

### M1 出口

至少一条拟支持路径在主要刘海／容量不足场景中完成真实用户任务，才继续将该路径接入产品垂直流程。

若只在空间充足的外屏成功，应明确记录其适用范围，不能宣称已经解决主要刘海场景。失败、未知和前置条件不成立同样是合格的研究交付，不是可以省略的结果。

## 5. 同步建立最小工程边界

以下是拟建模块，不是现有目录清单。可先在一个仓库中使用一个 Xcode App target 和内部 Swift Package。

| 模块 | 首批职责 |
|---|---|
| AppShell | NSApplication、常驻状态项、面板、设置、恢复入口 |
| Core | UserIntent、ObservedState、EffectivePlan、OperationReceipt、身份与布局纯模型 |
| Platform/Inventory | AX 有界读取、生产者与宿主区分、快照来源与新鲜度 |
| Platform/Visibility | 各候选几何／显隐适配器，声明真实控制粒度 |
| Platform/Access | Located 与动作提交、实际菜单证据的区分 |
| Coordination | 唯一命令执行循环、InteractionLease、ticket 与取消 |
| Persistence | 版本化 JSON、原子替换、上一个有效配置、最小恢复记录 |
| Diagnostics | OSLog、版本与操作 ID、有界本地导出 |
| Tests / Lab | 纯模型、适配契约、本工具 UI 和真实 Mac 任务记录 |

MainActor 持有 AppKit 对象。同步 AX IPC 和 AXObserver 使用适配器拥有的专用线程／RunLoop，跨边界传值。Coordinator 可使用 actor，但必须有单消费者执行循环；不能让多个 await 之间重新进入的调用同时改变布局。

LayoutPlanner 是纯计划器：返回计划给 Coordinator，由后者执行 VisibilityBackend 与 AccessBackend。AccessBackend 需要临时布局时返回需求，不自行重排。

VisibilityDomain 明确 individualItem、application、contiguousRange、ownItems 以及是否跨显示器共同生效。共享状态项的 length 不能表示同一项目在不同屏幕上有不同显隐状态。

AccessResult 至少有 located、actionSubmitted、observedMenuOpen、ambiguous、blocked、unsupported、outcomeUnknown；不得统一压成一个成功布尔值。

## 6. 不变量与针对性验证

这些规则应进入核心契约与必要测试，避免用大量与实现镜像的测试制造数量。

### 身份与版本

- 本地 LogicalItem UUID 不等于系统稳定 ID；PID、窗口号、frame、动态标题不是跨重启主键。
- 唯一的当前绑定才允许精确动作；重复标识或观察不完整返回歧义／未知。
- 用户别名只改善查找，不凭空创造稳定身份。
- inventoryEpoch 只因身份集合或绑定结构变化递增；普通值刷新更新 observationRevision。
- 本操作已验证的预期布局变更更新 applied 与中间态，不让自身 ticket 自动失效。
- 拓扑、权限或无法归因的外部变化使旧动作重新检查；迟到回调不修改新操作状态。

### 会话与恢复

- 租约锁住整个受影响显隐域，不只锁一个列表行。
- 菜单结束未知时，后台规则、自动收起和重排均不执行；计时器只能重新观察或提示。
- 使用 before / applied / current 三快照，只恢复仍属于本操作的最小字段。
- 每步逆操作后验证结果，再推进预期中间态；未知或不符就停止剩余逆操作并保留未解决记录。
- 用户的新布局优先。缺少拖拽通知不等于用户没有修改。
- 屏幕变化先废弃旧 ticket 与坐标，由新的 RecoveryIntent 决定安全动作；救援若中断菜单，如实记录中断。
- Task.cancel 不会自动撤销已经提交给第三方进程的动作。

### 配置、真实状态与可访问性

- 配置仍在与重启后布局可用分别验收。反复要求重新整理只能算部分支持。
- App 图标、AX 语义值和某一时刻的图像是不同来源；未知不填 0，旧画面不标实时。
- 本工具入口、目录、过滤、设置和恢复可用键盘与 VoiceOver 完成；第三方交互保留无管理器基线能力。
- 不依赖录屏的构建不展示假像素功能，也不要求用户预授不存在功能的权限。
- 新项目没有新的隐藏意图，不等于区间后端不会暂时挤走它；检测延迟与恢复必须真实测量。

## 7. 验收协议 v0.2 的有限修改

保留 protocol v0.1 原文件和历史结果，另建版本。新协议只增加范围声明与条件适用，不能放宽已经观察到的失败。

建议结果结构包括：

| 信息 | 用途 |
|---|---|
| environment / comparison_group_id | 绑定硬件、OS、拓扑与相符基线 |
| source_revision / source_hash / protocol_hash | 明确真实执行的输入 |
| claimed_capabilities | 本构建声明哪些能力 |
| case_applicability / exclusion_reason | 未实现项与适用条件分开 |
| expected / observed / status | 预期、观察与判定分开 |
| raw_evidence / observer_identity | 原日志、人工或 AI 观察来源 |
| support_decision | 支持范围、阻断项与未解决问题 |

普遍完整性门槛始终必测。声明或实际执行的能力必须跑对应任务。没有像素捕捉器可排除其专属前态，但不能填录屏撤回处理通过；缺设备、权限或时间保持 blocked / not_run，不伪装为不适用。

若修改评估器，只补与条件适用、历史失败保留和证据绑定相关的必要用例。评估器检查记录的一致性，不代表它已经重新操作过 macOS UI。

## 8. 通过 M1 之后的第一条产品流程

后续 M2 只先连通一条真实流程：

启动 → 用户组织常驻／收纳两区 → 点击或快捷键展开 → 基本过滤 → 唯一项目定位或打开原菜单 → 保持交互 → 用户明确收起。

再推进持久化、授权撤回、多屏变化、睡眠唤醒和迁移；通过后做键盘、VoiceOver、资源定标与可安装发行包。未证明任意第三方项目移动前，不做看似可任意排序的列表拖拽。

依赖按计划选用 KeyboardShortcuts、SMAppService 与 Sparkle 2，在实际工具链上锁定版本；用户选择登录启动与更新检查。正式发行采用签名、公证与更新包校验，保留全部第三方通知。源码、仓库和公开安装包的发布不属于这份首轮研究执行任务。

## 9. 最终交付格式

提交一个可复查结果包与一份简明报告，至少包含：

1. 实际构建日志、工具链／SDK、源码和协议版本；
2. 无管理器基线与各候选匹配记录；
3. 三个同 App 项目的身份观察，真实不可见状态与访问结果；
4. 原始日志、必要的任务观察、步骤、时间和引用关系；
5. 能力表：verified / experimental / unsupported / unknown，逐 Item-action 和条件登记；
6. 失败、未知、恢复步骤及用户布局是否保留；
7. 修改过的源文件、许可通知和复现入口；
8. 下一条具体实验及它要消除的不确定性。

报告必须分别回答：正确目标是否可达；原菜单是否继续可用；右键／Option／动态状态是否保持；是否中断正在使用的菜单；是否损害系统状态；是否覆盖用户新修改；当前哪种组合具备进入 M2 的条件。

“编译成功”“selector 存在”“收到 activation”“纯模型检查通过”分别只证明自己的事情，不能合并成上述用户任务已经通过。
