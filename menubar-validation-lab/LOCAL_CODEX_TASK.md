# 给本机 Codex 的执行任务

请在当前解压目录中推进 Menu Bar Validation Lab v0.1。目标是取得真实 Mac 基线与一个候选的证据，不是先写产品界面。

## 已经完成、不要重写的部分

已有 Fixture、几何 Controller、只读 Observer、私有接口只读探针、24 任务／50 变体协议和结果评估器。当前附带的结果来自 Linux：Python 检查已执行，Mac 编译与 UI 行为为 not_run。请阅读 README.zh-CN.md、protocol/RUNBOOK.zh-CN.md、backend-analysis/PRIMARY_FINDINGS.md 后再操作。

## 本机执行顺序

1. 使用 python3 tools/preflight.py 保存本机环境。记录实际 OS build、架构、开发工具；不要从用户过去描述或当前日期推断系统版本。
2. 运行 bash scripts/build-macos.sh，保留完整构建日志。若有 Swift / AppKit 兼容性编译错误，先做必要修复，再运行便携检查，并为实际构建输入记录新的 SHA-256；不把修复后的结果标为原源码成绩。
3. 先运行 Fixture.app。正常停用已有菜单栏管理器后，验证 FA、Beta、FC 的左键、右键、Option、子菜单、持续计数与日志。基线不成立的项目标 blocked 或 unknown，不归咎于候选。
4. 创建匿名机器名与 comparison_group_id；记录逻辑点屏幕拓扑、缩放、刘海、菜单栏自动隐藏、独立 Spaces 和权限 profile。不采集序列号、账号、与任务无关的应用内容。
5. 如当前为 macOS 26，先测 legacy_single_spacer_experiment；27 则测 guarded_native_overflow。其他系统只做观察，不修改硬编码门槛去冒充已获支持，也不升级系统。手动定位 Controller 占位项，再执行 protocol 里与实际能力相符的任务。
6. 先检查恢复入口、正确原菜单、右键/Option、菜单保持和系统状态，再测拓扑／权限／故障。发现错误目标、输入被抢、隐私状态被遮蔽或用户修改被覆盖时，停止继续扰动，撤销本实验限制，保留失败记录。
7. 5 秒延迟触发仅是实验刺激，10 秒请求展开也可能打断菜单。该版本没有菜单锁、规则引擎、Item 搜索和三分区；这些不能报告支持。不为了通过测试修改期望。
8. 如需权限，在正常系统设置中交由操作者完成；不修改 TCC、关闭 SIP、绕过系统安全或读取无关内容。未经实际观察，不声称授权完成。
9. 私有探针只执行 build/private-probe，记录类和 selector 的存在性。本任务不激活 MBAssessmentModeAssertion，不增加隐藏系统状态的实现。存在性全 true 仍不能填任何显隐任务 passed。
10. 操作者手动开启自己选定的摄像头／麦克风应用，观察系统指示与名称提示。没有设备、权限或观察条件时保留 blocked；不录制音视频。
11. 每个结果目录保留 results.json、原始 JSONL、文本操作记录及 hash。AI 观察记录标明 AI 身份；源码推断、日志事件和人工确认不可互换。
12. 用 tools/evaluate_results.py 对候选与匹配基线评估，保留退出码与输出。输出报告说明已测覆盖、失败、范围排除和下一项具体实验。先不要发布仓库、产品或二进制安装包。

## 成功标准

交付实际运行的编译日志、至少一个环境条件下的无管理器基线，以及与它匹配的候选原始记录。结果可以是失败或不足；关键是有可复现步骤和诚实的证据边界。

必须分别回答：

- 合成应用三个 Item 是否被精确区分？若系统不暴露稳定 AX ID，是否明确记录缺口？
- 用户是否打开并继续操作了正确原菜单？右键、Option、计数是否保持？
- 新触发和到期展开是否打断菜单，或覆盖用户新的布局？
- 刘海与外屏、系统时钟／通知中心、摄像头／麦克风提示是否完整？
- 正常退出与本实验进程故障后的真实恢复步骤是什么？
- 有哪些能力由于未实现、缺设备或权限而不能进入支持范围？

不要把“编译成功”“selector 存在”“收到了 activation”“Python 测试通过”写成这些用户任务已通过。
